# HAW021

Reports two distinct excessive-exception-handling signals.

First, it reports a `catch (System.Exception)` block with no filter when the
block's only statement returns `null`, `default`, `default(T)`, or the default
primitive/enum value. This is intentionally limited to catch-all failure
conversion without recovery; specific exception types, filters, logging,
rethrowing, and blocks that do other work are not reported by this signal.

Second, it reports a source class or struct when its count of `try` blocks per
eligible ordinary method exceeds the configured density. Methods are eligible
only when their implementation is in source; constructors, accessors,
abstract methods, and nested lambda/local-function `try` blocks are excluded.
The default requires at least five methods and more than 0.75 try blocks per
method.

HAW021 does not duplicate HAW013: exception wrapping is analyzed by HAW013,
while this rule's catch-level signal is limited to silent default returns. A
dense type can still receive its own type-level HAW021 diagnostic when that is
independently useful review evidence.

Configure `minimumMethodCount`, `maximumTryBlocksPerMethod` (greater than zero
and at most one), and `reportCatchAllDefaultReturn`. If a legacy protocol
needs independently isolated fallback boundaries, suppress the type locally
with a precise non-blank justification:

```csharp
[SuppressMessage(
    "Hawthorne.Reliability",
    "HAW021",
    Justification = "Legacy protocol requires independently recoverable fallback boundaries.")]
```
